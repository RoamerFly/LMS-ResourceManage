## 项目亮点

- **零门槛部署**：基于 Python + SQLite，无需安装数据库或 Node 环境，下载发行版双击"立杰工资管理系统.exe"直接启动，或下载源码双击 `run.vbs` 即可启动。
- **全离线运行**：数据全部存储在本地 `data.db`，核心工资计算不依赖任何外部服务。
- **双数据源工资计算**：支持"做货编辑"（订单+型号+对数）和"快捷计算"（部门+单价+对数）两种工资录入方式，一键切换。
- **类 Excel 录入体验**：做货编辑和快捷计算支持拖拽或 Shift+方向键选取单元格区域、区域复制粘贴、方向键与 Tab/Enter 导航、自动保存和撤销重做。
- **一键打包发布**：通过 PyInstaller 打包为单文件夹 exe，复制到任意 Windows 电脑即可运行，无需安装 Python。
- **个性化定制**：支持浅色/深色/自定义主题、多套配色方案、自定义字体上传、表格字号和布局调整。
- **数据安全**：数据库导入导出、业务数据清理、自动备份，数据迁移零门槛。

## 界面预览

### 资源总览

资源总览提供常用功能和其他功能入口，功能卡片支持拖拽排序，也可以自定义是否加入常用功能。

![资源总览](docs/images/screenshot-overview.png)

### 人员管理

人员以多列圆角卡片按部门分组展示。点击姓名直接编辑人员，卡片仅保留详情和删除按钮；支持新增、批量添加、批量删除、同部门内拖拽换位，以及按名称 Unicode 顺序升序 / 降序排序。页面中央的“部门管理”按钮打开大弹窗，以自顶向下的树状分支展示大部门和小部门，并可直接在节点中添加或删除部门。

![人员管理](docs/images/screenshot-members.png)

### 成员详情

成员详情展示当月工资汇总、做货明细、快捷计算来源明细和增扣记录。增扣记录支持同月多条，包含日期、增扣对数、增扣工资和理由，可新增、删除和批量删除。

![成员详情](docs/images/screenshot-member-detail.png)

### 银行卡管理

集中展示成员银行卡信息，默认隐藏卡号，支持一键切换完整卡号显示状态、双击卡片编辑、自动保存、一键更新开户行、同部门内拖拽排序，以及与人员管理页显示顺序同步。

![银行卡管理](docs/images/screenshot-banking.png)

### 做货编辑

做货编辑提供类 Excel 表格录入体验，支持订单号 / 型号下拉选择、前列冻结、部门提示行、自动保存、手动保存、清空对数、撤销重做、工资视角切换、列顺序拖拽和行合计实时刷新。

在做货编辑和快捷计算的对数视角，单击选中整个单元格，拖拽或 Shift+方向键选取连续区域；双击或按 F2 编辑，直接键入数字会覆盖当前单元格。Ctrl+C 复制所选区域，Ctrl+V 从 Excel/WPS 或本系统粘贴，Ctrl+A 选中当前表格，Delete 清空选区。方向键、Tab 和 Enter 移动当前单元格；单个值粘贴到选区会填满选区。粘贴只写入当前表格已有的可编辑单元格，超出边界的内容会提示并跳过。

![做货编辑](docs/images/screenshot-work-edit.png)

![工资视角](docs/images/screenshot-work-edit-salary.png)

### 快捷计算

快捷计算按大部门分组录入对数和单价，可实时计算行合计、部门合计和全厂合计。页面保留一条紧凑工具栏，表格占满窗口剩余高度。在紧接在用行的第一条空白行输入或连续粘贴即可录入，无需添加或删除行；禁止跳过空白行。清空中间整行后，后续数据向上补齐，末尾恢复普通空白行。快捷计算可作为总工资表和成员详情的工资数据源。

![快捷计算](docs/images/screenshot-quick-calc.png)

### 总工资表

总工资表按部门汇总全厂工资，支持做货编辑 / 快捷计算双数据源切换、显示顺序同步人员管理页、彩色打印和黑白打印。

![总工资表](docs/images/screenshot-salary.png)

系统设置支持极简模式、外观主题、颜色主题、字体、表格字号、布局、窗口参数、数据库导入导出、业务数据清理和自定义字体管理。

## 功能总览

### 基础资料

- 人员管理：维护姓名、性别、大部门、小部门，支持批量添加和批量删除。
- 成员排序：左侧竖向三点手柄用于同部门内拖拽换位；“按名称排序”按钮可按 Unicode 字符码点升序或降序排序，结果写入数据库。
- 部门管理：维护大部门和小部门，两级结构会影响工资汇总、快捷计算分组和成员排序边界。
- 订单管理：按年月维护订单号、备注和关联型号。
- 型号单价：维护型号在不同小部门下的单价，供做货编辑自动计算工资。

### 工资录入与计算

- 做货编辑：以订单、型号、成员为维度录入做货对数，支持同一订单型号组合多行记录。
- 快捷计算：不依赖订单和型号，按部门直接录入对数和单价，适合临时、快速或简化工资计算。
- 工资数据源：可启用“快捷计算作为工资数据源”，总工资表、成员详情和银行卡页的工资参考会同步切换。
- 行合计与总计：做货编辑和快捷计算均支持实时行合计、部门汇总和全厂汇总，避免切换页面后才刷新。
- 保存机制：做货编辑和快捷计算都保留自动保存，同时提供手动保存按钮。编辑中点击保存、刷新、切换页面或月份，会先提交当前单元格；保存请求按顺序写入，避免旧请求覆盖新数据。

### 电子表格操作

- 做货编辑、快捷计算使用 Univer 1.0.3 的 Canvas 电子表格引擎，显示行号、列字母、公式栏、工作表标签和缩放控件。双击人员姓名表头直接弹出“编辑人员”，先提交当前数字，再加载最新人员资料；保存后当前表格更新姓名、部门信息并保留已录入数据，工资视角也能继续使用。单击只选格；拖选、Shift/Ctrl 扩选或键盘移动到表头不触发人员弹窗。
- 单击选中单元格，拖动或 Shift+方向键选择矩形区域；Ctrl+C / Ctrl+V 直接复制粘贴整个区域，支持来自 Excel / WPS 的数字及单元格格式。
- 直接键入数字覆盖当前格；双击或 F2 编辑，Enter / Tab 提交并移格。选择状态下方向键移动当前格。
- 单元格字体、颜色、边框、数字格式，以及列宽、行高和缩放可调整；格式通过 `app_settings` 保存，按页面、年月和视角区分。
- 快捷计算按部门显示为工作表标签，没有“添加行”“删除选中行”按钮或选格说明。含非零单价或对数时自动显示在用行的颜色；整行清空或归零后不保存空白占位行。只能编辑现有在用行或紧接其后的第一条空行，允许连续多行粘贴，禁止包含空行间隔的新增录入。清空中间整行会将后续数据和格式向上补齐，末尾恢复白色空白样式；支持撤销和重做，刷新、重启仍保持连续数据。接近表格底部时自动扩展空白行。仅显示表头对应的业务列，单价和员工列均可直接录入，表头之外禁止写入。
- 选中快捷计算的员工列后，可从紧凑工具栏中的员工菜单打开详情或调整列顺序。做货编辑仍在表格上方选择订单、型号和删除行。
- 左侧导航默认自动适应文字宽度，字体放大时同步扩展。应用默认以最大化窗口启动，窗口设置中仍可手动调整。

#### 录入与保存回归验证

在安装项目 Python 依赖、Node.js 22+ 和 Microsoft Edge 后运行：

```powershell
node tests/spreadsheet-selection-native.cjs --engine
node tests/spreadsheet-selection-native.cjs --live
node tests/spreadsheet-selection-native.cjs --management
```

`--management` 使用隔离数据库验证多列圆角人员卡片、卡片姓名编辑、做货/快捷计算表头双击编辑与保存、数据保留与工资视角恢复、拖选及键盘不误触、人员与部门树新增、订单页单价保存、极简模式三卡片导航、全宽主页、工资来源、退出恢复和重启持久化。

`--engine` 验证真实鼠标拖选、剪贴板粘贴、多位数字、撤销重做、格式保留，以及连续空白行自动启用、清空、扩展、禁止跳行和数值校验。`--live` 使用生产页面及 HTTP API，在临时目录创建独立 SQLite 数据库，验证双击输入、编辑中保存、刷新、切页、切月、服务重启后恢复、禁止跳行、清空中间行后自动收拢及撤销重做、表头之外禁止写入、空白行不保存，以及紧凑布局和窗口默认设置；不会写入项目或发行包的业务数据库。可通过 `TEST_PYTHON` 指定测试解释器，默认使用项目 `venv/Scripts/python.exe`。
- 录入、批量粘贴与格式修改接入统一撤销 / 重做。表头、工资显示及合计为只读，对数仍须为非负整数，单价允许小数。
- 此处提供业务录入电子表格，不包含任意 XLSX 文件导入导出、宏、图表和 Excel / WPS 的全部功能。

### 成员详情与增扣

- 成员详情按年月展示个人工资、做货明细和增扣明细。
- 做货明细会跟随工资数据源切换；快捷计算来源下，订单号和型号显示为“来自快捷计算”。
- 增扣记录支持一个成员同一个月多条明细，字段包括增扣日期、增扣对数、增扣工资和增扣理由。
- 增扣记录支持新增、单条删除和批量选中删除。

### 银行卡资料

- 银行卡管理页仅用于资料展示和编辑，不包含打款逻辑。
- 卡片双击进入编辑，默认开户人为成员名，资料自动保存。
- 卡号默认打码显示，顶部眼睛按钮可切换完整显示；完整显示时按每 4 位加空格格式化，显示状态持久化保存。
- 支持一键更新开户行：根据银行卡号调用支付宝公开卡 BIN 接口，并通过 `b.json` 将银行缩写映射为银行全称。
- 支持同部门内拖拽换位和“显示顺序同步人员管理页”。

### 显示顺序与拖拽

- 人员管理页的成员顺序保存在数据库 `employees.sort_order`。
- 总工资表、做货编辑、快捷计算和银行卡管理均提供“显示顺序同步人员管理页”开关。
- 关闭同步后，相关页面可维护自己的手动列 / 卡片顺序；这些偏好写入 `app_settings`，不依赖临时 localStorage。
- 拖拽采用“拖拽项与目标项直接交换”的方式，并带有交换成功动画。

### 打印与显示

- 总工资表提供“彩色打印”和“黑白打印”两个按钮。
- 彩色打印保持当前界面视觉配置，黑白打印使用更适合黑白纸张的打印样式。
- 打印会调用本机 `127.0.0.1:8765` 页面进行浏览器打印。
- 普通页面文字可选中复制；录入电子表格按单元格选择复制，进入编辑后可选择格内文字。

### 个性化设置

- 主题模式：浅色、深色、柔和混合、跟随系统。
- 颜色主题：内置多套配色，也支持自定义主要颜色、背景、卡片和文字颜色。
- 字体设置：支持系统字体、自定义字体上传和字体大小调整。
- 表格设置：支持表格字号、密度、行高等显示参数调整。
- 窗口设置：支持分辨率、最大化、全屏等配置，重启后生效。

### 数据维护

- 数据库导入 / 导出：可将当前 `data.db` 导出备份，也可导入 `.db` 文件覆盖当前数据。
- 设置导入 / 导出：可导出界面设置 JSON，也可导入恢复。
- 业务数据清理：可按条件清理做货记录、增扣记录和快捷计算保存数据。
- 单实例运行：Windows 下会阻止重复打开多个程序实例，减少端口冲突和数据误操作。

## 快速开始

### 环境要求

- Windows 7 / 10 / 11
- Python 3.8+

### 启动方式

```bat
run.vbs
```

也可以在命令行运行：

```bash
python main.py
```

首次启动会初始化本地数据库，并在 `127.0.0.1:8765` 启动 FastAPI 服务，再由 pywebview 打开桌面窗口。

### 生成测试数据

```bash
python seed_data.py
```

如果需要生成测试用例数据，可运行：

```bash
python seed_data_test.py
```

## 打包发布

### 图形菜单打包

```bat
build.bat
```

菜单选项：

- `1`：普通打包，无控制台窗口，推荐日常使用。
- `2`：调试打包，保留控制台窗口，便于排查启动问题。
- `3`：清理 `build/` 和打包文件，保留 `dist/` 中的运行数据。
- `Q`：退出。

### 命令行打包

```bash
python build.py
python build.py --debug
python build.py --clean
```

打包使用 PyInstaller 的 `--onedir` 模式，产物位于 `dist/立杰工资管理系统/`。发布到其他电脑时，复制整个产物文件夹即可，不需要目标电脑安装 Python。

构建前请保存数据并关闭发行目录中的软件。Windows 发行文件被占用时，脚本会在开始清理前停止，并提示关闭软件。

打包脚本优先使用项目的 `venv`，并在清理旧产物前检查 FastAPI、Uvicorn 等运行依赖和 PyInstaller；缺少依赖时会停止构建。首次打包可先在项目虚拟环境中安装 `requirements.txt` 和 PyInstaller。

离线电子表格资源已随源码提交，EXE 运行时无需下载 CDN 资源。修改引擎依赖或构建入口时，先运行 `npm ci` 和 `npm run build:sheet`（需要 Node.js）。`python build.py` 在前端构建依赖可用时会自动重新构建，并在清理旧产物前核对资源清单。

表格集成验证：`node tests/spreadsheet-selection-native.cjs --engine`（Node.js 22+、Microsoft Edge，可通过 `EDGE_PATH` 指定浏览器路径）。该测试在独立配置目录中使用真实鼠标、键盘和系统剪贴板，覆盖区域复制粘贴、数据写回、合计、撤销重做、格式保存与部门切换。

重新打包和清理时会保留 `dist/立杰工资管理系统/` 中的 `data.db`、`window_settings.json` 和用户字体目录。

打包内容包含：

- `web/` 前端页面资源。
- `database/` 数据库结构文件。
- `services/` 后端服务模块。
- `b.json` 银行缩写与银行全称映射。
- `立杰鞋业工资管理系统.ico` 程序图标。

核心数据表：

- `departments` / `sub_departments`：大部门和小部门。
- `employees`：成员资料和人员管理页排序。
- `employee_bank_accounts`：成员银行卡资料。
- `orders` / `order_models`：订单及其关联型号。
- `models` / `model_prices`：型号和各小部门单价。
- `work_records`：做货编辑记录。
- `salary_adjustments`：成员增扣明细。
- `quick_calc_saves`：快捷计算保存数据。
- `app_settings`：工资数据源、显示顺序同步、主题和其他偏好设置。

## 常用工作流

### 建立基础资料

1. 在“人员管理”页点击中央“部门管理”，维护大部门和小部门。
2. 在“人员管理”中添加成员，并按部门调整显示顺序。
3. 在“订单管理”页切换到“型号单价表”，维护型号和对应小部门单价。
4. 在“订单管理”中创建订单并关联型号。

### 使用做货编辑计算工资

1. 进入“做货编辑”，选择年月。
2. 添加行，选择订单号和型号。
3. 在成员列录入做货对数，系统自动计算行合计。
4. 进入“总工资表”查看汇总并打印。

### 使用快捷计算计算工资

1. 在首页开启“启用快捷计算作为工资数据源”。
2. 进入“快捷计算”，按部门录入单价和对数。
3. 保存后，总工资表、成员详情和银行卡页会使用快捷计算结果。
4. 如果关闭该开关，系统回到做货编辑数据源。

### 维护银行卡资料

1. 进入“银行卡管理”。
2. 双击成员卡片编辑银行卡、开户人、开户行、预留手机和备注。
3. 如果已填写卡号，可点击“一键更新开户行”自动补全开户行。
4. 需要完整卡号时点击顶部眼睛按钮，状态会在下次启动时保持。

## 接口与开发

后端接口默认运行在：

```text
http://127.0.0.1:8765
```

接口文档可参考 [API_DOC.md](API_DOC.md)。常用模块包括：

- `/api/employees`：成员资料。
- `/api/employees/order`：人员管理页排序持久化。
- `/api/bank-accounts`：银行卡资料。
- `/api/bank-lookup`：开户行查询。
- `/api/orders`：订单管理。
- `/api/models` 和 `/api/price-table`：型号与单价。
- `/api/work-records`：做货记录。
- `/api/adjustments`：增扣记录。
- `/api/salary-summary` 和 `/api/qc-salary-summary`：工资汇总。
- `/api/quick-calc-save`：快捷计算保存。
- `/api/app-settings`：系统设置和页面偏好。
- `/api/database/export` 与 `/api/database/import`：数据库备份与恢复。

开发启动：

```bash
pip install -r requirements.txt
python main.py
```

前端为原生 HTML / CSS / JavaScript，不需要 Node 构建步骤。修改 JS 后可用下面命令做基础语法检查：

```bash
node --check web/js/member.js
```

## 故障排查

### 127.0.0.1:8765 无法访问

- 确认没有旧程序占用端口。
- 尝试使用 `python main.py` 调试启动，查看控制台错误。
- 如果是打包版，建议先用 `build.bat` 选择调试打包，保留控制台输出。

### 打包后开户行查询失败

- 确认打包产物目录中包含 `b.json`。
- 确认电脑可以访问 `https://ccdcapi.alipay.com/validateAndCacheCardInfo.json`。
- 开户行查询依赖银行卡号的卡 BIN 信息，如果接口未返回 `validated: true`，系统无法准确映射开户行。

### 数据需要备份或迁移

- 推荐在“系统设置 -> 数据”中导出数据库。
- 也可以在程序关闭后复制 `data.db`。
- 打包版的 `data.db` 位于 exe 同级目录。

### 重复启动提示或端口冲突

系统默认启用单实例限制。若异常退出后仍无法启动，可检查是否有残留的 `立杰工资管理系统.exe` 或 `python.exe` 进程。
